# Spec: 批量图片工作流

## Objective

在 Vela 首页增加“批量工厂”。用户一次上传多张商品/人物图片，可再上传一张全批次共享的对标图，配置一个共享的图生图任务，即可创建一个 Vela 项目，并在该项目画布内为每张图片建立一个独立、可重试的工作流分组。创建项目不提交付费任务；用户勾选工作流并点击“批量开始生成”后才提交任务。批次可选择发布到编导车间（Storyworks）及多个已配对的自制软件。

共享提示词区增加“AI 智能分析”。用户选择已配置的 GPT 或 Qwen 视觉模型后，模型会结合当前需求、最多 4 张批量产品图和可选对标图，生成一条可直接用于图生图节点的中文提示词。分析结果先预览、后采用，不在用户确认前覆盖当前提示词。用户还可以把当前提示词保存到本机提示词库，并在后续批次中直接选择复用。

新建批次还可附加“姿势裂变”后缀工作流。主图节点生成满意结果后，用户在画布中启动后缀节点，一次生成多张不同方向/动作的独立图片；后缀只允许改变人物姿势，人物身份、裤子与其他服装的款式/颜色/材质、背景、构图、镜头、光线和文字排版保持不变。

首页“电商工作流”区域增加“批量工厂”项目分类。批量工厂创建的项目只出现在该分类，不混入普通“项目”分类；旧版已经创建的批量项目也通过批次索引自动归类。

## Assumptions

- 一个批次只创建一个项目。无对标图时，每张输入图对应“商品原图 → 主图生成 → 姿势裂变”；有对标图时，对应“商品原图 + 对标图 → 主图生成 → 姿势裂变”。
- 对标图为可选的批次共享输入；文件只持久化一次，但在每个独立分组内建立清晰标注的对标图节点，并与该组主图节点连线。
- 姿势裂变为可选后缀，默认开启；后端保持向后兼容，旧客户端未传该参数时不会改写已有两节点工作流。
- 比例、清晰度、GPT 账户/图片模型、每图张数、提示词和项目名称是批次共享参数。
- 姿势裂变张数为 2-10 张，默认 5 张；每张任务获得不同的前、后、左、右或自然运动方向提示，禁止拼图。
- 首次默认同步目标是编导车间；用户可在同步窗口选择多个已配对软件。每个软件获得独立批次清单和项目/结果引用，不覆盖目标软件数据。
- 单批最多 50 张、单图最多 100MB，每图输出 1-10 张。
- 智能分析一次最多发送前 4 张产品图和 1 张对标图；模型选择来自已有 GPT 兼容账户的“提示词模型”或“Qwen 分析模型”。
- 输入框中的现有提示词在需求未单独填写时作为分析目标；分析预览只有在用户点击“采用这条提示词”后才写回图生图提示词。
- 保存的提示词进入 Vela 本机数据目录，保存名称最长 80 字，正文最长 4000 字，不包含账户密钥。

## Tech Stack

- React 19 + TypeScript + Vite 前端。
- Express 本机服务。
- 现有 ProjectStore、ProjectMediaStore、JobRepository 和 GPT 图片编辑执行链。
- 批次索引使用数据目录内的原子 JSON 文件；旧版多项目批次会合并生成一个新项目，原项目目录和历史任务保留为隐藏兼容数据。
- 批量任务进入终态后，将输出 URL、节点状态和进度回写项目文档；打开项目时会先对批次任务和画布节点做一次幂等校准，以修复历史遗留的 `loading / 0%` 节点。

## Project Structure

- `src/vela/components/VelaBatchFactory.tsx`：上传、参数配置、批次项目表和批量操作。
- `src/vela/services/batchWorkflowService.ts`：批次 API 类型与请求。
- `server/vela/batchWorkflowStore.js`：批次持久化、项目创建、提交任务和同步清单。
- `server/routes/vela-data.js`：批次 REST 路由。
- `server/vela/batchWorkflowStore.test.js`：持久化与防重复提交测试。
- `src/vela/components/VelaEcommerceWorkflows.tsx`：普通项目与批量项目分栏展示。
- `src/vela/components/VelaPromptWorkbench.tsx`：视觉模型选择、需求输入、分析预览和提示词模板选择/保存。
- `src/vela/components/useVelaPromptWorkbench.ts`：提示词模板与视觉分析的异步状态、过期请求隔离和文件读取。
- `server/vela/promptTemplateStore.js`：本机提示词模板的原子持久化。
- `server/providers/openAiCompatibleProvider.js`：GPT/Qwen 通用多图视觉分析请求。

## Testing Strategy

- Node 单元测试：单项目多工作流分组、共享对标图、四节点连线/参数、姿势后缀配置、批量提交、防重复提交、同步清单。
- 回归测试：成功、失败和取消任务正确回写画布节点；旧批量项目可自动合并、归类并修复结果。
- TypeScript：检查组件和服务类型。
- Vite build：检查生产编译。
- 手工检查：空状态、错误状态、键盘操作、320/768/1024/1440 宽度布局。
- 视觉分析回归：GPT 与 Qwen 槽位均使用用户选择的模型；产品图和对标图标签顺序稳定；预览不会自动覆盖提示词；API Key 不进入请求响应和提示词模板。

## Boundaries

- Always：复用现有项目和任务系统；创建与开始生成分离；原子保存批次索引；保留已有项目与用户素材。
- Ask first：新增第三方同步目标、改变数据库 schema、安装依赖、生成安装包。
- Never：把 API Key 写入项目或批次；删除失败批次中的已创建项目；重复提交已有任务；覆盖 Storyworks 数据。
- Never：把视觉分析交给图片生成模型猜测；在用户点击采用前覆盖提示词；把超过 4 张产品图或超过 1 张对标图发送给分析接口。

## Success Criteria

- 用户上传 10 张图并点击创建后，项目列表只新增 1 个项目，画布内包含 10 个互相独立的工作流分组。
- 共享参数正确写入每个图生图节点，全部输入素材持久化到同一个项目目录。
- 上传对标图时，每组都显示“商品原图”和“对标图”两个输入节点，并共同连接到主图节点；批量提交会按连线顺序携带两张参考图。
- 开启姿势裂变时，每组主图后都创建一个独立后缀节点，默认输出 5 张，生成模式为 `pose-variation`；主图没有结果时会明确阻止启动。
- 姿势后缀以主图当前结果作为唯一参考，只改变姿势，不改变人物、服装、背景、构图、光线和文字等细节。
- 批量开始只提交勾选且未提交的工作流，再次点击不会重复产生任务。
- 批次表展示每个工作流的草稿、排队、生成中、完成或失败状态，并可打开所属项目画布。
- 批量工厂页面顶部不再显示说明性大标题，提供“新建项目”按钮用于清空当前草稿并开始下一批。
- 首页“批量工厂”分类只展示批量创建的项目，普通“项目”分类不再混入这些项目。
- 批次任务完成后，打开画布时图生图节点显示已生成图片，不再停留在“正在制作 0%”。
- 一键同步会先打开目标选择窗口，再为 Storyworks 或已配对软件分别生成清单并记录逐目标结果，不修改任何来源项目。
- 刷新或重启 Vela 后仍能读取批次和任务状态。
- 用户可从同一账户的 GPT 提示词模型或 Qwen 分析模型中选择视觉分析模型；未配置时界面给出前往 API 设置的明确入口。
- 智能分析把需求、产品图和可选对标图一并发送，返回内容只包含可直接执行的图生图提示词，并显示实际使用的账户与模型。
- AI 结果先进入预览区；采用后才替换当前提示词，取消或分析失败均保留原文。
- 当前提示词可命名保存，重启软件后仍能从下拉框选择并写回提示词区。
