# 后端电商工作流实施计划

1. 将 10 个工作流清单改为显式输入契约和引擎路由，首页/项目只生成精简节点图。
2. 增加视频输入节点与 Wan 处理节点，前端按角色收集并持久化图片、视频和文字素材。
3. 在服务端实现 Wan UI 图输入注入、远端 `/workflow/convert`、ComfyUI prompt 提交、状态轮询与结果落盘。
4. 保持 MiniMax H3 为普通新视频生成引擎，保持 GPT 中转为全部作图引擎。
5. 增加密码加密的跨电脑迁移包和 AutoDL/ComfyUI 可复现部署说明。
6. 运行测试、构建、界面验收和敏感信息扫描；递增补丁版本并原位更新桌面应用。
7. 使用显式文件范围提交 Git，推送 GitHub，建立草稿 PR，并发布供另一台电脑更新的安装包。

## Validation checkpoints

- 清单恰好 10 条：8 条 `gpt-image`，2 条 `wan-video-process`。
- 项目中的全部 `parentIds` 有效，且不存在原 ComfyUI 内部节点。
- Wan 两个工作流的输入分别命中固定图片/视频节点 ID。
- 非图片不能进入 GPT 图片参考；非视频不能进入 Wan 视频输入。
- 加密迁移包用错误密码无法解密，明文扫描不出现已保存秘密。
- `npm run test:node`、`npm run build`、安装版健康检查与 GitHub 发布检查全部通过。

## Risks and mitigations

- Wan 图含 Set/Get/Reroute 等虚拟节点：不自行重写转换器，依赖远端正式加载图后转换；缺插件时立即给出安装提示。
- 云实例可能关闭或产生费用：本地测试使用桩服务，真实远端验证前先检查电源状态并获得授权。
- SSH 私钥路径不可跨电脑：只在密码加密迁移包内携带内容，导入后写入新的应用数据私钥目录并重写路径。
- 工作区含大量既有改动：逐文件检查与显式暂存，不使用 `git add -A`。
